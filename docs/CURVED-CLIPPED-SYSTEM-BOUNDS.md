# Certified curved clipped system bounds

This stage closes the native rest-mapping and beam-header dependency on non-crossing curved system clips. It reuses the original global neighbor areas. The area library clips x-monotone quadratic/cubic Bezier segments with the pinned Order2/Order3 inverse and subdivision operations, then obtains normalized y extrema. Boundary control hulls must prove strictly positive band height inside the canvas throughout the clip. Integer bounds use floor/ceil, and header-left uses the certified clip edge. There is no sampling, column heuristic, or general boolean Area operation. Crossing bands and non-monotone Bezier control hulls remain unsupported.

The unmodified original SystemManager.computeSystemArea, Area.getBounds, StaffManager.getClosestStaff, SystemInfo.getStaffAtOrAbove and Rectangle.intersects oracle records eight configurations. Six curved target-system bounds are supported, including quadratic/cubic extrema, nonuniform x spacing and a near-integer maximum; two deliberate crossing/non-monotone cases remain negative controls. Original closest/above queries and lag-section rectangle intersections match on supported targets. Pure geometry adaptation preserves a nonempty shared graph. Existing header and rest tests now positively exercise their previously unsupported valid curved clips.

Four existing horizontal raster inputs retain the supported BEAMS.EPILOG boundary. These controls do not demonstrate a positive real-score rest conversion. The validated prior source 7bc4213c passed 321 tests in each debug/release full profile; full suites are unverified at this new source.

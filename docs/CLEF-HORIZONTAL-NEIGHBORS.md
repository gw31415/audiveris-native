# Side-by-side clef browse geometry

Native ClefBuilder candidate analysis now uses original StaffManager vertical-neighbor chains for browse rectangles, rather than rejecting horizontally separated staffs and limiting clipping to adjacent vector entries. Every neighbor whose integer abscissas strictly enclose the browse midpoint contributes the original rounded ordinate and half-gap ceil/floor bound. Midpoints exactly on neighbor endpoints do not contribute. Inner-rectangle constants, candidate extraction, classifier grading and registration retain the pinned original behavior.

Original private getOuterRect/getInnerRect controls cover side-by-side, skipped neighbors, touching endpoints, curved lines and independently observed Laura geometry. A new actual side-by-side raster composed from preserved rendered treble and bass fixtures is run through original GRID, ClefBuilder candidates and registration; native ROI, glyph pixels, candidate grades and registered clef bounds are compared to that oracle. Existing positive/negative raster clef controls remain checked. Candidate and registration functions retain staff IDs, and shared GRID graph ownership/identity is checked unchanged during these pure stages.

This stage does not implement a full multi-column score pipeline or assign provisional clefs into an authoritative complete SIG. The full native CLI records the next actual unsupported boundary; stem-seed and beam/rest adapters and clipped area bounds remain unfinished. No positive real-score rest conversion is claimed. Full regression at this source remains unverified.

# Brace, part and page checkpoint

Official source: Audiveris 5.11.0 `9e1e55cd2746037d059345881c53e6a6754bffbd`, AGPL-3.0-or-later. This is an independent brace checkpoint; bracket/C-clef recognition and overall stage-order integration are not complete.

## Translated algorithms

`StaffProjector.findBracePeak/createBracePeak` searches the actual per-staff projection, uses left blanks and the valley threshold, extends to the left blank and chooses the right valley minimum. `BarsRetriever.lookForBracePeak` applies section-width, height, curvature and staff-end extension checks. Portion filaments use the same core/touch expansion as `BarFilamentBuilder`/`BarFilamentFactory`. `buildBraceFilament` joins portions and expands through touching sections whose boxes are contained in the piecewise linear brace area. No image-specific coordinates or part boundaries are inputs.

`BraceInter.getBounds` extends the actual glyph box to the closest staffs' outer lines using staff area containment and vertical distance. Glyph pixels and interpretation bounds intentionally differ.

The default `createGroups/isTrueBraceGroup/createParts` brace rule accepts exactly two embraced staves only when they have non-start-bar internal connections and no non-start-bar external connections. Defaults `forceSinglePart=false`, `forceSeparateParts=false`, `disconnectedBracedParts=false` are preserved. Unrecognized brace topology reports unsupported and suppresses part output. Bracket/square group metadata is pending.

`SystemManager.checkIndentation/allocatePages` uses the deskewed left/top coordinates and a two-interline indentation threshold under the default enabled indentation switch. This allocates logical page/movement sections of the input sheet, not PDF pages or a completed score.

## Independent comparison

`scripts/official_brace_probe.py` observes brace portions after each original BarsRetriever method. The Java algorithms are unchanged. Native input is the original raster, not oracle membership.

On AnLaura:

- Four detected brace portions match official staff ID, peak coordinates, TOP/BOTTOM classification and every section identity/orientation.
- Both complete brace glyphs match official origin, box, orientation and every run. Pixel boxes are `(214,517,16,164)` and `(52,1029,15,172)`; interpretation boxes become `(214,516,16,167)` and `(52,1028,15,173)` through the source rule.
- All **38 interpretations, 30 relations and 50 registered glyph originals** now match final official GRID by content. Java numeric IDs are not copied.
- System 1 parts are `[1]` and `[2,3]`; system 2 parts are `[4]` and `[5,6]`. Both match official part descriptors. One logical page contains systems `[1,2]` and starts a movement.
- The synthetic no-brace system remains 7 interpretations, 3 relations, two separate one-staff parts, one page without a movement start.
- StaffLine, HLAG/VLAG, system memberships, exact residual pixels and 604 raw connected components remain covered by the existing regression tests. Components are not notes.

## Still pending

- `detectBracketEnds/getSerif/buildSerifFilament`, `detectBracketMiddles` and bracket/square group descriptors.
- Long-brace fallback through an aligned ordinary bar (`checkBraceAlignment`). This is explicitly unsupported, not approximated.
- Full `purgeLeftOfBraces`, `verifyLinesRoot`, C-clef rejection, freeze propagation and general exclusion-aware SIG contextualization.
- Unifying semantic peak mutation and endpoint calculations in the full official method order. Early partial-column/too-left prerequisites are reproduced before brace search; right-end refinement is still calculated by the earlier geometry pipeline. The tested fixtures agree, but other layouts can differ.
- Nondefault switches, multiple interlines, side-by-side systems and general music recognition/MusicXML.

`grid_complete:false` remains mandatory. The present fixture match does not establish general recognition accuracy.

## HEADS handoff decision

Use versioned templates generated by the official implementation with the native numerical core, not approximate pure-Rust font rasterization. Audit found only 6/15 raster cases pixel-identical and meaningful score/bounds differences. The small fixed Bravura bank and strict native loader will carry final keypoints/anchors, including width-based size correction and whole-note double-size rendering. Unknown shapes/sizes are unsupported; Java remains a development-time asset generator only. Keep the audit's AGPL/OFL/font SHA provenance. The template core candidate remains commit `593d1c5d4cddfed4085371ef6a25447151a923d0`; no HEADS code is integrated here.

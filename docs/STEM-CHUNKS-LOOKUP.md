# Section catalog to registered STEMS candidates

Run `audiveris-native stem-chunks-lookup REQUEST.json REPORT.json`. The destination must not exist. The request uses schema `audiveris-native.stem-chunks-lookup-request.v1`, vertical/horizontal section catalogs and searches with supplied linear polygons, lookup parameters, initial physical catalog, existing IDs, optional stump ID/head physical glyph, VIP flag and alignment limits. See `scripts/stem_chunks_lookup_request.py` and the gzip fixture request for a complete example.

Each search has an independent canonical registry. Its initial catalog order allocates IDs starting at 1; duplicate canonical initial entries refuse. Existing/stump IDs must refer to that same catalog. All raw chunks are registered before existing/HEAD/alignment removal. Excluded glyphs remain in the output registry. The stump is removed once and surviving candidates are stably sorted by direction. The report contains selected sections/raw physical glyphs, registered/retained IDs, counts and the final physical registry. Input/catalog/search/pixel/work/output-run/byte limits apply; invalid late input is rejected before creating a report, and existing outputs are preserved.

3,048 original 5.11 controls on 612 legitimate Laura first-system builders compare the complete original lookupChunks results against this actual CLI, including null stump, repeated existing IDs, HEAD VIP and empty raw input. Geometry, final theoretical lines and upstream head/beam context are supplied. This is a useful replay/inspection CLI stage; it does not yet choose page neighborhoods/targets, expand stem items/gaps/length maps, grade/cache final stems, connect heads, update page SIG or run the STEMS epilog. HEADS/STEMS completion flags remain false. Nonzero skew, real scans, special staff and 24-shape full-page propagation are unverified. Historical kernel, 13 same-Laura controlled conditions and three independent synthetic pages remain distinct scopes.

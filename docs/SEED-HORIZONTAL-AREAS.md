# Native stem seeds in clipped neighbor-chain areas

Seed staff selection uses the original StaffManager rule: filter system staffs by each original global staff area's containment, including system horizontal clipping, then choose the smallest algebraic vertical distance after Java integer truncation. Membership order wins equal distances. The native neighbor-chain area implementation supplies containment for straight and curved boundaries. The previous adjacent-vector single-column approximation and blanket clip rejection are removed. Supplied ends must match those discovered from actual SystemInfo coordinates; malformed membership, unsupported staff line counts, resource limits and downstream unsupported boundaries retain explicit errors.

An independent original SystemInfo.getClosestStaff observer supplies positive and absent selections over nine configurations, including exact clip edges, fractional offsets, horizontal and vertical chains, curved boundaries and independently observed Laura GRID geometry. A two-column treble/bass raster is also processed by original GRID, live HEADERS and VerticalsBuilder: four accepted seeds across two systems. Native candidates, closest staff IDs, header filtering, accepted glyphs and original StemChecker grades are compared. Existing eleven raster seed controls remain checked. Shared GRID graph identity is unchanged during the pure seed computation.

This completes this seed-area adapter. Beam header preparation, general horizontal beam/rest adapters and clipped boolean area bounds/edges remain unfinished. Positive stem seeds are not positive real-score rests or complete OMR. Debug and release full regressions are recorded separately in the checkpoint validation receipts when run; do not infer them from focused checks.

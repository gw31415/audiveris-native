# Native vertically stacked multi-system rest mapping

SystemMapping now uses globally ordered native GRID staff curves to build original staff areas, but restricts closest/at-or-above selection and detector profiles to the requested system's staves. System staff IDs must flatten to the global staff order, with unique staff/system identities and full-sheet horizontal system-area ends. Unequal horizontal staff spans are supported when all staves share a nonempty x overlap and their vertical bands are separated. Horizontal staff chains, disjoint columns, overlapping bands, clipped system ends and tablature remain explicit unsupported cases.

For each staff, original StaffManager.computeStaffArea uses global neighboring staves even across a system boundary. Area assembly retains horizontal endpoint extensions, curved Bezier segments and the measured rounded sheet margin. Closest selection still uses area containment, integer-truncated distance and encounter-order ties; at-or-above fallback uses the previous staff in the same system, never a preceding staff from another system.

Original MultipleRestsBuilder.getSectionsByWidth reads complete vLag then hLag and retains section rectangles intersecting SystemInfo.getBounds, with a stable abscissa sort and width checks at the serif stage. SystemInfo.getBounds comes from the system area, not the staff coordinate box or centroid-based GRID section IDs. The native mapper uses the exact noncrossing band path's Y extrema, floor/ceil rectangle conversion and strict rectangle intersection; original width/peak checks remain in the existing filament algorithm. The Area helper exposes assembled path extents before cancellation and is used only for validated noncrossing full-width bands.

MultiSystemAreaControlProbe reproduces unmodified original StaffManager/SystemManager area construction and SystemInfo selection using the independently observed Laura original GRID curves. Its 324 selection cases (98 selections, 226 no-staff results) cover both systems, boundary points and cross-system gaps. Original bounds are [0,0,1489,876] and [0,692,1489,1412]. Supplied section rectangles verify bounds-intersection retention; they do not claim native ledger discovery or positive rest recognition.

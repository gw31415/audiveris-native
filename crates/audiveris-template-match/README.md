# Audiveris distance / template numerical core

Independent Rust translation from Audiveris **5.11.0**, commit
`9e1e55cd2746037d059345881c53e6a6754bffbd`. Production code uses only Rust std;
no Java, AWT, OCR, image library or font engine is used at runtime.

Implemented:

- The exact default 3/4 chamfer forward/backward traversal, foreground and background targets, normalizer 3.
- `DistanceTable.Short` signed narrowing behavior (`Storage::JavaShort`) and integer storage. `overflowed()` reports any short narrowing. The 12,000-pixel row golden reproduces Java's wrapped negative distances, including propagation of negatives other than -1. Choose `Integer` deliberately if avoiding that upstream behavior; it is not an identical replacement on overflowing inputs.
- Pixel-mask portion of `DistancesBuilder`: whiten selected locations before distance propagation, then neutralize those same locations to -1.
- Known-template `Template.evaluate`, `evaluateHole`, and integer anchor offsets, including side-dependent 0.001 bias and Java rounding.
- Explicit dimension, allocation, coordinate, finite-value and resource checks. Invalid inputs can return errors where Java might throw/wrap. Empty image dimensions are rejected; empty templates and no usable reference pixels retain Java's score sentinels.

**This is not a complete native notehead detector.** Template rasterization,
staff/ledger/stem selection, candidate scanning, cross-head boosts, competition,
inter creation and later recognition stages are outside this crate. The other
official chamfer kernels and `DistanceTable` graphical/ROI methods are not ported.

## Semantics that matter for integration

`pixels` and returned distance values are row-major. Byte 0 is foreground; every
other byte is background. No targets gives -1 throughout. `neutralize` does not
recompute distances. The caller supplies the *same* ignored mask before/after
propagation using `compute_masked_foreground`.

`DistancesBuilder.paintLines` selects staff-line glyph pixels **plus complete
staff curves across crossings**, ledgers and vertical seed glyphs (excluding
tablature staff in the staff pass). A simple NO_STAFF connected-component image
does not reproduce this stage's input. The selection/curve rasterization is not
implemented here; see the preserved official source.

Despite the name, 5.11.0's template score compares **binary foreground/background
agreement**, not the numerical difference of distances. Expected d=0 uses weight
6, d>0 weight 1, and d<0 (hole) weight 4. Actual -1 and points outside the page are
ignored. Actual zero is foreground and any other value is background. No included
weight returns `f64::MAX`; no usable hole points returns hole ratio 0. The default
weights match official defaults. Custom weights are an explicit extension.

```rust
use audiveris_template_match::*;
let pixels = [255, 0, 255, 255];
let distances = compute(2, 2, &pixels, Target::Foreground,
                        Storage::JavaShort, Limits::default())?;
let template = Template::new(vec![KeyPoint {x:0, y:0, distance:0.}],
                             Limits::default())?;
let result = template.evaluate(&distances, 1, 0, None, Weights::default())?;
assert_eq!(result.score, 0.0);
# Ok::<(), Error>(())
```

## Evidence and regeneration

`fixtures/java-golden.json` was generated by **unmodified official release JAR**,
bundled Java 25.0.3 (Zulu), macOS arm64, headless. The adapter compiles with JDK21
and calls official code reflectively. It contains:

- 32 full distance arrays: empty reference, all foreground, corner targets,
  gray nonzero background, ignored mask, narrow column and short overflow row;
  both Fore/Back and Short/Integer.
- 3 actual Bravura templates at point size **44**: NOTEHEAD_BLACK 17×15/152 points,
  NOTEHEAD_VOID 17×15/155 points, WHOLE_NOTE 23×15/238 points.
- 21 actual anchor offsets and 120 score/hole-ratio pairs, including image edges,
  partial clipping, wholly outside, and ignored pixels. Equality is exact f64,
  with serde_json's `float_roundtrip` enabled to avoid parser-induced ULP errors.

Generation calls `MusicFont.populateAllSymbols`, then official
`TemplateFactory.getCatalog(Bravura,44)`, `getTemplate`, and `getKeyPoints`.
The factory's binarization threshold is 140. Its own hole fallback rebuilt
WHOLE_NOTE at 88 and reduced it back to the requested resolution; the unchanged
factory produced that result. No hand-drawn or approximate templates are used.
AWT rasterization can vary across platforms/JDKs, so checked-in fixtures fix this
environment's output. Native generation for arbitrary point sizes is still needed.

Bundled font: **Bravura version 1.392**, 512,924 bytes, SHA256
`dca2d90c88437a701b1c2e71fa54e76f9fa41d7deee935d74dc871ea66ecfdd2`.
The exact font's embedded license and provenance are retained; the font itself
and the Java distribution are not bundled. Synthetic page inputs are CC0.

```sh
# AUDIVERIS_CONTENTS points at Audiveris.app/Contents from official 5.11.0.
# JAVAC points at an available JDK compiler (21 used in this run).
python3 oracle/generate.py
cargo test --offline
cargo test --offline --release
cargo clippy --offline --all-targets -- -D warnings
```

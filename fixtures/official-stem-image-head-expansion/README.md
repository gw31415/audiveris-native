# Image head expansion and actual cache creation

Original Audiveris 5.11, pinned upstream 9e1e55cd2746037d059345881c53e6a6754bffbd:
two independently compiled observers run on XML-loaded Laura HEADS. All head
builders are inspected before expand/createStem at fixed default profile1.
No native report, endpoint, selected parts or pixel filter overrides enter the
observer. Whole original linkStems ordering, SIG registration and epilog are
not invoked. This is distinct from a fully automatic original/native pipeline.

The native `--head-stems` image CLI performs the same inspection-boundary
expansion from its own image-derived stumps/linkers/chunks/items, using the
same owned physical registry and actual per-system caches. No XML, Java or
fixture is read at native runtime. NO_STAFF pixels from the actual upstream
owner grade selected unions. All1408corners match selected parts, stop indices,
relations, final stem geometry/grade and cache-hit state;409positive creations
correspond to43/51unique system cache entries. Twelve direct original controls
separately cover centroid shifts, overlap, canonical duplicates, null glyphs
and below/equal/above maximum-dx ULPs in both orientations.

Old reports and their recorded hashes remain unchanged. Historical source
hashes are verified against published source commit
3d2482fe6e28a1912c3bc03dfbe53cd628092e47/tree
be0e81f3e7738a7af45543b249040b50495dfcf8, rather than relabelled as current
production source. The new reproduction records current source-file hashes.
The checkpoint MANIFEST pins the resulting source commit/tree and all files.

at the inspection boundary. Beam-origin builders, original scheduler/reuseStem,
live head/beam SIG attachment, cleaner/checkNeededStems/beam-finalizer epilog

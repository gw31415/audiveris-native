# Selected original StemBuilder.filter

4,152 controls use legitimate original Head CLinker and Beam VLinker builders
initialized by original StemsRetriever.process on the first Laura system.
All612 observed builders participate. Actual stored candidates are used in
empty/actual/reversed-and-aliased modes with optional source bounds clipping;
480 additional prescribed rectangular-glyph controls cover both run orientations,
both directions, short parts and object aliases. This is a selected filter
boundary, not automatic discovery or complete page STEMS parity.

Two independent Audiveris5.11 observer compilations and executions reproduce
raw results byte for byte. Native retained parts/linker order, lastHeadY,
item kind/identity/contribution and every fitted center-line coordinate match
exactly. Controls include1974 null starting stumps,1680 zero-width y ranges,
312 nonnull Beam lastHeadY values,324 removed part entries and36 removed linker
entries. Registry/cache/SIG and physical input glyphs are unchanged by the
native pure plan. Java positive object tags are caller identities, not JVM
numeric IDs or GlyphIndex content IDs.

Observed skew0 and maximum7 candidate linker entries are compared. Nonzero skew,
32 or more candidate linkers, and single-pixel fitted items explicitly refuse.
The small-list sort preserves Java's stable run/binary-insertion behavior;
larger TimSort merge behavior needs a separate original comparison. Native
custom head-stop/clipping, empty range, invalid identity/nonfinite parameter
and resource-budget checks are distinct from independently observed controls.

Automatic raster/seed/section discovery and lookup area derivation, full builder
item sorting/gap/length expansion, cache-to-head composed connection, finalizers
and epilog remain pending. Prior selected kernels, the13 same-Laura control
conditions, independent synthetic font/cue pages and Laura352/513/all8 report
SHA256 are preserved. HEADS24 whole-page propagation, arbitrary special staff,
published score scans and complete HEADS/STEMS remain unverified and false.

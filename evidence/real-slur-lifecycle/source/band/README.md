# Exact rectangle routing prerequisite

Eight generic noncrossing Bands cover lines, quadratics, cubics with two Y extrema, vertical tangency, full-width paths and clipped paths. 1,570 rectangle queries per Band include exact boundary-only contact, tiny positive overlap, empty/negative extents, far points, wide rectangles and deterministic noninteger controls.

Actual original runtime `java.awt.geom.Area.intersects` and pinned `SystemManager.getSystemsOf(Rectangle2D, found)` run on detached original SystemInfo objects carrying those Areas. The manager preserves supplied System order, clears a supplied result list and returns that same list. No Book was loaded or saved; no image processing was invoked.

`/tmp/area_rect_proposal.rs` applies OpenJDK Curve/Order1 crossing operations and Order2/3 vertical-extremum rules to the existing native normalized Y-monotone edges. The source operation order was read from the installed JDK21 source archive; expected results are independently observed from the original application's actual JDK25 runtime. This extends the existing independently licensed `audiveris-area` library and keeps its GPL-2.0 + Classpath Exception boundary.

The isolated Rust comparison has **12,560 Area decisions plus 4,710 route/order/reused-list checks = 17,270 comparisons, zero differences**. This measured coverage does not prove arbitrary self-intersecting, overlapping or general boolean paths. The proposed Band method requires a sufficient construction certificate: globally X-monotone connected top/bottom curves with strictly separated control hulls. Its native clipping intersects the query rectangle with the existing clip, using set-intersection equivalence without polygon approximation.

`/tmp/slur-native-hookup-unit/B-exact-band-rectangle-routing.patch` adds this method to the retained actual Band. Source full-width Bands are not clipped to image height; partial-width Bands are, matching the current Band contract and the original controls. The production patch is not compiled or run. This comparison concerns generic geometry, not actual native image/System/Staff integration. Previous native-curve transfers used original SystemManager and remain separately qualified.
